# Wibrawl reels, hero navigation, and brand socials

The three approved hero designs are preserved. Wibrawl has no hero Play/Pause button. Slides rotate every six seconds, support directional arrows within the image stage, and support horizontal touch/pen swipes. Manual navigation resets the rotation delay. Mouse hover, keyboard focus, hidden tabs, and reduced-motion preferences suspend automatic rotation. Vertical touch gestures keep native page scrolling; a swipe across a product link cannot open it.

Three separate product edits appear below the store promises: Filmstrip (native horizontal scrolling with staggered imagery), Spotlight (one featured product, thumbnail selection and text navigation), and Lookbook (an asymmetric product grid). These use the existing approved product images, real product links, and no Play/Pause or arrow buttons. No additional inventory, prices, reviews, categories or social accounts are created.

From either domain's shared admin, open Hero Studio and choose Wibrawl in the Hero storefront selector. The Cinematic Reel Studio below it has independent Show switches, mouse/touch drag ordering, keyboard Up/Down ordering, live Gaming/Sports previews, editable copy, and selection of up to eight live Wibrawl/shared products per reel. Empty selection uses a variant-balanced automatic selection. Any subset of zero to three reels is supported. Queue visibility and order save immediately; copy/product changes use Save reel.

Storefront settings contains a Socials storefront selector. Glamia profiles use the existing `socials` record; Wibrawl profiles use `wibrawl_socials`. Empty profiles remain hidden. Wibrawl starts with empty links, with no fallback to Glamia. Shared business controls and Glamia-specific SEO remain explicitly identified in the same admin. Social URLs retain HTTPS/platform validation.

The existing cinematic-reel admin API is scoped by the authorized storefront selector. Glamia's singular record is unchanged; Wibrawl's three-reel document uses `wibrawl_cinematic_reels` in the existing `storefront_settings` table. Ordered updates validate all three unique styles and eligible product IDs before a single atomic write. No database schema migration is required. Existing employee storefront/cinematic-reel permissions govern the same shared routes on both domains. Public settings are scoped by hostname; a public query cannot select another brand. Homepage, product and cart bootstraps use their own brand's settings. Cache invalidation reaches the selected production origins, including changes made from the other brand's admin.
